# ✈️ Preflight

**Чи готовий ваш застосунок, створений за допомогою вайб-кодингу, до запуску? Дізнайтеся однією командою.**

Preflight сканує ваш проєкт на наявність витоків ключів, відкритих баз даних, неперевірених платежів і відсутніх базових елементів запуску, а потім надає картку звіту з виправленням для кожного виявленого факту.

```bash
npx vibe-preflight
```

Без встановлення, без облікового запису, без мережевих викликів. Ваш код ніколи не покидає ваш комп’ютер.

## Чому

Інструменти ШІ дозволяють легко створити застосунок за вихідні, і так само легко випустити його з секретним ключем Stripe у бандлі браузера або таблицею Supabase, яку може читати будь-хто. Preflight перевіряє помилки, які найбільше болять після запуску, ще до запуску.

## Спробуйте спочатку на зламаному застосунку

```bash
npx vibe-preflight --demo
```

Сканує навмисно зламаний демонстраційний застосунок (усі секрети вигадані), щоб ви побачили, як виглядає звіт із помилками.

## Що перевіряється

23 перевірки сьогодні, у сфері безпеки, надійності та базових елементів запуску. Див. [усі перевірки](rules.md).

| | |
|---|---|
| 🔑 Живі секрети в коді клієнта | 🗄️ Таблиці Supabase без безпеки на рівні рядків |
| 📄 Файли `.env`, які можна закомітити | 💳 Вебхуки Stripe без перевірки підпису |
| 🌍 CORS, відкритий для всіх сайтів | 🚨 Відсутній моніторинг помилок |
| 🔒 Відсутня політика конфіденційності | 🔗 Відсутні заголовок, опис або зображення для поширення |

## Параметри

```bash
npx vibe-preflight [path]          # scan a folder (default: current folder)
npx vibe-preflight --html          # also write a shareable preflight-report.html
npx vibe-preflight --json          # machine-readable output ([JSON format](json.md))
npx vibe-preflight --ignore a,b    # skip checks by id
npx vibe-preflight --fail-on warning   # exit code policy: critical (default) | warning | never
```

Встановіть NO_COLOR=1, щоб вимкнути кольоровий вивід.

Щоб заглушити виявлення, яке вказує на рядок, додайте `// preflight-ignore <check-id>` у цей рядок або в рядок вище. Виявлення, що стосується цілого файлу (закомічений `.env`, неперевірений вебхук), потребує такого самого коментаря в перших п’яти рядках файлу. Усе, що ви хочете прибрати в межах усього проєкту, зокрема виявлення без файлу, використовує `--ignore <check-id>`.

## Використання в CI

```yaml
- run: npx vibe-preflight --fail-on critical
```

Команда завершується з кодом 1, коли виявлення досягає рівня `--fail-on`, тож витік ключа блокує злиття. Див. [ci.md](ci.md) — повний робочий процес.

## Використання в Claude Code

Preflight постачається як плагін Claude Code з командою `/preflight`, яка запускає сканування, пояснює результати та пропонує виправляти критичні проблеми по одній, запитуючи перед кожною зміною.

У Claude Code виконайте:

```text
/plugin marketplace add erdellll/preflight
/plugin install preflight@preflight
```

Потім введіть `/preflight` у будь-якому проєкті.

## Додайте перевірку за 10 хвилин

Кожна перевірка — це один маленький файл плюс дві папки з прикладами: одна, яку треба позначити, і одна, яку треба залишити в спокої. Без кроку збірки, без залежностей. Прочитайте [CONTRIBUTING.md](../CONTRIBUTING.md) або оберіть issue з міткою [`good first issue`](https://github.com/erdellll/preflight/issues?q=is%3Aopen+label%3A%22good+first+issue%22).

## Не аудит безпеки

Preflight виявляє поширені помилки з високим впливом за допомогою швидких перевірок за шаблонами. Чистий звіт означає, що жодна з його перевірок не спрацювала, а не те, що ваш застосунок безпечний. Використовуйте його як ремінь безпеки, а не як заміну перевірці.

## Часті запитання

**Чи надсилає Preflight мій код кудись?**

Ні. Preflight повністю працює на вашому локальному комп’ютері, не здійснює мережевих викликів і не збирає телеметрію. Ваш код ніколи не покидає ваш комп’ютер.

**Чи означає оцінка 100/100, що мій застосунок безпечний?**

Ні. Це означає лише, що жодна з перевірок Preflight не виявила проблеми. Докладніше див. у розділі [Не аудит безпеки](#не-аудит-безпеки).

**Як заглушити хибне спрацювання?**

Використовуйте `// preflight-ignore <check-id>` у відповідному рядку або `--ignore <check-id>` під час запуску Preflight. Також відкрийте issue на GitHub із міткою або заголовком "False positive", щоб перевірку можна було покращити.

**Які стеки він розуміє?**

Preflight може сканувати файли будь-якого проєкту, але його перевірки найкраще працюють із Next.js, Vite, Supabase, Stripe, Express і звичайним HTML.

**Чому файл із символічним посиланням не перевіряється?**

Символічні посилання пропускаються навмисно — і файли, і папки. Якщо йти за ними, можна зациклитися — папка, пов’язана сама з собою, ніколи не закінчується — і можна прочитати файли поза проєктом, який ви попросили Preflight просканувати. Тому `.env`, що є символічним посиланням на файл в іншому місці, не повідомляється; скопіюйте його в проєкт або спрямуйте перевірку на папку, де він справді міститься. Коментар до `walk` у `src/project.js` каже те саме поруч із кодом.
